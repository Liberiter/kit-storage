# Kit — python-programming / fundamentals

「바람재 관측망」이라는 하나의 이야기 위에서 코스의 모든 예제와 문제가 돕니다.
이 폴더에는 그 이야기의 자료 파일과, 실습 환경을 세우고 확인하고 되돌리는
스크립트가 들어 있습니다.

환경은 이 코스의 기준을 따릅니다 — CPython 3.14, 프로젝트 환경은 `.venv`,
도구는 pytest·Ruff·mypy입니다. 컴퓨터에 파이썬을 직접 설치해서 쓰고,
컨테이너는 쓰지 않습니다. 0장이 안내하는 **두 경로를 모두 지원합니다** —
기본 경로(uv가 파이썬까지 맡습니다)와 대안 경로(여러분이 설치한 파이썬 +
`venv` + pip). 같은 `./check_env.sh` 가 두 경로 모두를 판정하고, 통과 판정도
같습니다.

## World — 바람재 관측망

산자락에 흩어진 작은 기상 관측망입니다. 관측소 여섯 곳이 2025년 11월 한 달
동안 날마다 최저·최고 기온과 강수량, 하늘 상태를 적어 두었습니다.

```
바람재 관측망
├─ 산마루 권역
│  ├─ 윗재   — BJ 바람재(612m, 유인)  · SD 솔등(447m, 자동)
│  └─ 너미골 — NM 너미(158m, 자동)   · GS 갈숲(355m, 자동)
└─ 들녘 권역
   ├─ 하곡   — HG 하곡(93m, 유인)
   └─ 물레   — MR 물레(238m, 자동)
```

| 자료 파일 | 담긴 것 |
|---|---|
| `data/readings.txt` | 관측 기록 180줄. 한 줄이 한 관측입니다 — `관측소\|날짜\|최저기온\|최고기온\|강수량\|하늘상태` |
| `data/readings.json` | 같은 기록을 관측소별로 묶어 담은 것. 같은 사실을 다른 모양으로 적으면 어떻게 되는지 보는 자리입니다 |
| `data/stations.json` | 관측소의 자세한 정보와 위 그림의 나무 구조 |
| `data/field_log.txt` | 현장 수첩을 그대로 옮겨 적은 기록 26줄. 칸이 들쭉날쭉하고, 재지 못한 자리는 「결측」이며, 이제는 쓰지 않는 관측소도 남아 있습니다 |

| 폴더 | 무엇이 있나 |
|---|---|
| `examples/` | 코스가 함께 읽는 예제 프로그램들 |
| `broken/` | 일부러 고장 내 둔 파일들. 실행하거나 도구에 물려 보면서 오류 화면을 읽는 데 씁니다 |
| `work/` | **여러분의 자리**입니다. 여기에 `.py` 파일을 만들어 실행하세요 |
| `out/` | 프로그램이 만들어 내는 결과 파일 자리 |
| `exit/` | 코스 마무리 문제의 답을 적는 자리 |
| `cases/` | 예제가 예상대로 도는지 자동으로 맞춰 보는 데 쓰는 파일들 |

자료 파일은 `make_world.py` 가 만듭니다. 날짜·시각을 읽지 않고 무작위 값도
고정된 씨앗에서 뽑으므로, 몇 번을 다시 만들어도 같은 내용이 나옵니다.

## 사용법

```bash
./setup.sh         # 처음 한 번 — 파이썬·도구 준비 + 자료 파일 만들기 + 환경 확인
./entry_check.sh   # 시작할 준비가 되었는지 확인 (입장 점검)
./check_env.sh     # 환경만 다시 확인
./reset.sh         # 자료 파일을 처음 상태로 되돌리고 out/ 을 비웁니다
./verify.sh        # 예제가 예상대로 도는지 자동으로 맞춰 보기 (기본 ./cases)
```

여러분이 만든 프로그램은 실습 폴더에서 이렇게 실행합니다.

```bash
uv run python work/first.py          # 기본 경로
.venv/bin/python work/first.py       # 대안 경로
```

## 두 경로 — 기본(uv) / 대안(시스템 파이썬 + venv + pip)

0장의 두 경로를 **같은 스크립트**가 받습니다. 어느 경로를 쓰셔도 명령은
그대로입니다 — 어느 쪽으로 도는지는 스크립트가 알아서 가릅니다.

| | 기본 경로 (`KIT_MODE=uv`) | 대안 경로 (`KIT_MODE=venv`) |
|---|---|---|
| 전제 | uv 0.12 이상 | 여러분이 설치한 CPython 3.14 |
| 파이썬을 어디서 얻나 | uv가 `uv python install 3.14` 로 내려받아 관리합니다 | 여러분이 설치한 것을 씁니다 (Homebrew·apt 등) |
| 도구를 어떻게 넣나 | `uv sync --frozen` 이 `uv.lock` 대로 | `python3.14 -m venv .venv` 뒤 pip이 `requirements-lock.txt` 대로 |
| 프로그램 실행 | `uv run python <파일>` | `.venv/bin/python <파일>` |
| 경로 지정 | 기본값이라 적지 않아도 됩니다 | **`KIT_MODE=venv ./setup.sh` 한 번**. 그 실행이 경로를 기억하므로 이후에는 붙이지 않아도 됩니다 |
| `./check_env.sh` 의 판정 | 같습니다 | 같습니다 |
| `./verify.sh` | `cases/` 전량 통과 | 같습니다 |

대안 경로 실행 예:

```bash
KIT_MODE=venv ./setup.sh       # 한 번만 — 이 실행이 경로를 기억합니다

# 이후에는 KIT_MODE 없이 그대로
./check_env.sh
./reset.sh
./verify.sh
```

파이썬 실행 파일의 이름이 `python3.14` 가 아니라면 `KIT_PYTHON` 으로 알려
주세요 — `KIT_MODE=venv KIT_PYTHON=python3 ./setup.sh` 처럼 씁니다.

두 경로의 인터프리터는 **만들어진 빌드가 다릅니다.** 코스의 예제는 그 차이에
걸리지 않게 짜여 있지만, `sys.version` 처럼 빌드 자체를 찍어 보는 코드를
직접 써 보시면 화면이 서로 다릅니다. 그것은 고장이 아닙니다.

### 구축 경로 기억 — `.kit-mode`

`KIT_MODE` 를 적지 않았을 때 어느 경로로 도는지는 다음 차례로 정해집니다.

1. **환경 변수 `KIT_MODE`** — 적으면 언제나 이깁니다.
2. **파일 `.kit-mode`** — `./setup.sh` 가 구축에 성공했을 때 자기가 쓴 경로
   (`uv` 또는 `venv`)를 한 줄로 적어 둔 파일입니다.
3. **그 파일도 없으면** — `uv` 명령이 있으면 기본 경로, 없으면 대안 경로로
   봅니다.

파일 내용이 `uv` 도 `venv` 도 아니면 스크립트가 종료 코드 2로 막고 그 파일을
지우라고 안내합니다. 이 파일은 여러분 컴퓨터의 상태이지 학습 자료가 아니므로
저장소에 추적되지 않습니다.

### 윈도우를 쓰신다면

윈도우에서는 **WSL2 배포판(우분투) 안에서만** 씁니다. 파이썬·uv·도구를 윈도우
호스트에 설치하지 않습니다 — 스크립트는 리눅스 셸에서 돌고, 호스트에 설치한
파이썬은 그 셸과 맞물리지 않습니다. 편집기(VS Code)는 윈도우에 두고 WSL 확장으로
배포판 안의 이 폴더를 여시면 됩니다.

WSL2 밖의 셸(Git Bash 등)에서 스크립트를 부르면 아무것도 하지 않고 그 사실을
알려 드립니다.

### 터미널의 글자 인코딩

이 코스의 자료와 화면에는 한글이 들어 있습니다. 터미널이 주고받는 글자
인코딩이 UTF-8이어야 교재의 화면과 같은 모양이 나옵니다 — macOS와 우분투는
기본값이 UTF-8이므로 따로 하실 일은 없습니다. `./check_env.sh` 가 이것도 함께
봅니다.

## 여러분의 자리 — `work/`·`out/`·`exit/`

- `work/` — 여러분이 만드는 `.py` 파일의 자리입니다. `./reset.sh` 도
  `./setup.sh` 도 이 폴더를 건드리지 않습니다.
- `out/` — 프로그램이 만들어 내는 결과 파일의 자리입니다. `./reset.sh` 가
  **비웁니다** — 실습을 다시 처음부터 해 보실 수 있도록 하기 위해서입니다.
- `exit/` — 코스 마무리 문제의 답을 적는 자리입니다. `./setup.sh` 가 답안
  파일이 없으면 만들어 드리고, **이미 있으면 손대지 않습니다.** 적어 두신
  내용은 다시 구축하거나 되돌려도 그대로 남습니다.

## 상태 되돌리기 — `./reset.sh`

```
되돌리기 완료: 관측 기록 180건, out/ 비움
```

되돌리는 것은 `data/`·`examples/`·`broken/` 의 파일들과 `out/` 의 내용입니다.
자료를 고쳐 보다가 원래대로 돌아가고 싶을 때, 그리고 파일을 쓰는 실습을 다시
해 볼 때 쓰세요. 여러분이 `work/` 에 만든 파일과 `exit/` 에 적은 답은 지우지
않습니다.

## 입장 점검 — `./entry_check.sh`

이 코스의 입장 점검에는 **풀어야 할 문제가 없습니다.** 파이썬을 처음 배우는
분을 전제한 코스라서, 확인하는 것은 아는 것이 아니라 환경이 제대로 섰는지
입니다. 두 단계로 봅니다.

```
== 1단계: 환경 확인
환경 확인 통과: 파이썬 3.14.7, pytest 9.1.1 · ruff 0.16.8 · mypy 2.3.1, 자료 파일 이상 없음 (경로: uv)
== 2단계: 예제 실행 확인
PASS 01-readings-summary
...
결과: PASS 6 / FAIL 0
입장 점검 통과: 환경과 예제 실행을 모두 확인했습니다 (경로: uv).
```

마지막 줄의 `입장 점검 통과: ` 를 보시면 시작하실 준비가 된 것입니다.
(파이썬과 도구의 자세한 판 번호는 설치 시점에 따라 조금씩 다를 수 있습니다.)

## 실패했을 때 — 화면의 첫 낱말이 어디서 온 말인지 알려 줍니다

스크립트는 실패할 때 **무엇이 잘못되었는지 한 줄, 다음에 무엇을 하면 되는지
한 줄**을 냅니다. 줄 앞의 낱말이 어느 검사에서 온 말인지 가리킵니다.

| 화면의 첫 낱말 | 뜻 |
|---|---|
| `구축 실패: ` | `./setup.sh` 가 환경을 세우다 막혔습니다 |
| `환경 확인 실패: ` | `./check_env.sh` 가 어긋난 자리를 찾았습니다 |
| `입장 점검 미통과: ` | `./entry_check.sh` 의 두 단계 가운데 하나를 넘지 못했습니다 |
| `reset 실패: ` | `./reset.sh` 가 되돌리지 못했습니다 |
| `verify 실패: ` · `entry check 실패: ` | 그 스크립트가 실행 전 점검에서 막혔습니다 |
| `오류: ` | 셸·상태 파일·인자처럼 실행 자체를 막는 문제입니다 |
| `  다음: ` | 바로 위 줄의 문제를 풀기 위해 하실 일입니다 |

종료 코드는 `0` 성공, `1` 어긋난 자리 있음, `2` 실행 자체가 불가(셸이 맞지
않거나, 상태 파일이 깨졌거나, 같은 자료를 쓰는 다른 실행이 돌고 있음)입니다.

같은 자료를 쓰는 실행이 겹치면 결과가 실행할 때마다 달라지므로, 스크립트는
기다리지 않고 **거절합니다.** 그럴 때는 먼저 돌던 실행이 끝난 뒤 다시
실행하세요.

## kit이 판정하지 않는 것 — 여러분의 개인 설정

kit이 예제를 실행하고 판을 확인할 때 부르는 파이썬은 여러분 홈에 둔 개인
설정(대화형 시작 파일 `PYTHONSTARTUP`, `PYTHONPATH` 같은 값)을 **읽지
않습니다.** 그 설정이 화면에 줄을 보태면 검사가 여러분의 잘못이 아닌 일로
실패하기 때문입니다. 바꿔 말해 그 설정이 만드는 차이는 **여러분이 직접
파이썬을 부를 때만의 것**이고 kit은 그것을 판정하지 않습니다.

**한 자리만 예외입니다** — 터미널의 글자 인코딩을 잴 때는 여러분이 직접 실행
하실 때와 **같은 조건으로** 부릅니다. 그 조건에서 재야 여러분 화면이 교재와
같은지 알 수 있기 때문입니다(위 「터미널의 글자 인코딩」). 그때도 읽는 것은
인코딩 한 가지뿐이라, 개인 설정이 화면에 줄을 보태도 판정이 흔들리지
않습니다.

## 예제 맞춰 보기 — `./verify.sh`

```bash
./verify.sh                 # ./cases 의 케이스를 모두 실행해 기대 출력과 맞춰 봅니다
./verify.sh <다른 폴더>      # 다른 폴더의 케이스로
```

코스를 만들고 검토하는 쪽이 주로 쓰는 도구이지만, 실습 환경이 제대로 서
있는지 스스로 확인하고 싶을 때 실행하셔도 됩니다. `PASS`/`FAIL` 과 마지막
`결과: ` 줄을 보시면 됩니다.
